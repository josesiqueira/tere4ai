# Cost estimate for the B74 sequence (dry run)

> Generated by scripts/estimate_benchmark_cost.py (B120). No model was called,
> no API key was read and no network was touched. Every step ran the real
> pipeline code with counting clients, so every prompt is the one a live run
> sends. Token counts are characters over a ratio measured per model developer, and
> output carries a declared reasoning band. This is an estimate, not a measurement.

## Models and prices

- The generator is gpt-6-astra (openai, effort high): 10.00 USD in / 50.00 USD out per MTok, Batch 5.00 / 25.00; https://developers.openai.com/api/docs/pricing, read 2026-10-04.
- The judge is claude-opus-5-5 (anthropic, effort high): 4.00 USD in / 20.00 USD out per MTok, Batch 2.00 / 10.00; https://platform.claude.com/docs/en/about-claude/pricing, read 2026-10-04.

Both ids come from the environment (TERE4AI_GENERATOR_MODEL and TERE4AI_JUDGE_MODEL),
checked against config/model_parameters.json; the prices are in config/model_prices.json.
Regenerate with TERE4AI_GENERATOR_MODEL=gpt-6-astra and TERE4AI_JUDGE_MODEL=claude-opus-5-5
exported: `.venv/bin/python scripts/estimate_benchmark_cost.py`; nothing else outside the
tracked tree changes a figure: the repository's .env, when present, is loaded, but an exported
variable wins over the file, and no other variable it may set reaches a figure.
Input is priced uncached: the clients send no cache_control (Anthropic caches nothing)
and record no cached tokens; automatic caching on the OpenAI side can only lower the figure.
Every request stays under 272,000 input tokens (asserted; the largest is 17,627), so the short-context prices apply. Standard tier.

The first run costs 23.91 USD (band 8.91 to 40.16) and each repetition after it 11.67 USD (band 5.35 to 18.54). The first run runs every condition on every case; each repetition after it runs conditions 1 and 2 on every case and conditions 3 to 6 on question and retrieval cases only, since no model call decides a classification case's scored outcome there (spec G D-G84 (5)), and the runtime judge is called on question and retrieval cases only (D-G84 (4)). The main run is priced at N = 11, the most the pilot run's rule allows (D-G84 (5): the smallest odd N reaching a half-width of 2 percentage points, at most 11), so the figure errs high; at the pilot's N, take the first run plus (N minus 1) times one repetition after the first.

A scenario without facts is counted with its explanation call: in the dry run it takes a stand-in of its own text with no flags, so conditions 3 to 6 call the generator to explain the classifier's level as a real run with elicited facts does; the estimate before B150 left those calls out (B150 ruling R32).

The pilot run (spec G D-G84 (5) and its dated paragraph (10)) repeats the ladder 5 times on a random sample of the development set (the REF-15 items outside the frozen sample) with the frozen sample's composition: 47 items, 32 scenarios (8 per risk level) and 15 question pairs, drawn from seed 20261011; its scenarios need the elicitor's facts first (the elicitation row). Its size is the main run's benchmark size, so that it measures the run-to-run spread at the main run's size (B150 Q10, Claude's choice on Jose's "If this is only about a pilot run not the full run then you can choose").

## Alignment rationale: a proxy, and the cost without it

- A stored assertion's rationale is the judge's, not the generator's (the pipeline keeps the judge's on the assertion), and no record holds the generator's own reply (the logs keep hashes only). The alignment step therefore uses the judge's rationale as a proxy for the generator's, in the generator's output and in the judge's input. The direction of the proxy's error is unknown, because the generator's rationale is not recorded: it may be shorter or longer.
- Sensitivity calculation, not a bound: the total without the rationale in both places is 364.76 USD central (182.52 low, 564.48 high), against the stated total of 408.92 (194.36 low, 643.57 high).
